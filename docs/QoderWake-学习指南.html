Step 01 · 用最简单的话解释

想象你开了一家公司

你每天要处理代码审查、Bug 修复、Issue 分类、告警分析……这些事情每一件都需要人去做，但你只有一个人。你不可能 7×24 小时不睡觉。

费曼第一步 · 简单解释

QoderWake 就是帮你「招」一批不会累的数字员工。它们住在你的电脑上，7×24 小时在线。你可以跟它们聊天派活，也可以设好规则让它们自动干活——就像管理真人团队一样。

更具体地说：QoderWake 是 Qoder 推出的数字员工平台。你在自己的机器上（或云端）安装它，然后创建多个「Waker」（数字员工），每个员工有自己的名字、角色、技能、记忆和权限。它们可以独立工作，也可以协同配合。

类比 · 一句话理解

把 QoderWake 想象成一个「AI 版的人才市场 + 办公系统」。你从市场里选角色（后端工程师、测试工程师……），给它们分配工位（项目/代码仓库），告诉它们能做什么不能做什么（权限），然后它们就开始上班了。

它的 Slogan 是：「Always awake, always working.」——全天在线，永不下班。

Step 02 · 深入核心概念

什么是 Waker（数字员工）？

Waker 是 QoderWake 的核心概念。每一个 Waker 就是一个独立的数字员工，有自己的五层架构——就像真人员工有身份证、技能证书、工作手册、岗位职责和行为准则一样。

1
身份 Identity
定义员工是谁——名字、角色定位、红线策略。纯文本管理，可 Git 版本控制。
2
记忆 Memory
保留长期上下文——对项目、对用户的认知积累。跨环境重启存活，本地存储。
3
技能 Skills
决定能调用哪些工具、执行什么操作。可从 Skills Marketplace 安装或自定义上传。
4
分工 Division of Labor
处理复杂任务的分解与协作，让多个员工可以协同完成大型工作。
5
权限红线 Permission Red Lines
定义哪些操作需要人工审批——核心分支、生产数据、高危命令等边界。
费曼检验 · 用类比检验理解

想象你要招一个后端工程师。你会给他：(1) 一个工牌（身份）；(2) 一份项目文档让他熟悉（记忆）；(3) 开 Jira、Git、CI/CD 的账号（技能）；(4) 告诉他负责哪些模块（分工）；(5) 强调「不能直接 push 到 main」（权限红线）。

QoderWake 对每个 Waker 做的事情，和你入职一个新员工的流程一模一样。

员工与工作空间解耦

QoderWake 做了一个重要的架构决策：员工和工作站是分离的。

概念包含什么特点
员工 Waker身份、记忆、技能、权限可跨设备迁移，跟随你的账号
工作站运行时环境可以是本地 PC，也可以是云沙箱

这意味着你的数字员工的「人格」和「能力」是绑定在员工身上的，而它在哪里运行（你的 Mac mini 还是云服务器）只是一个执行环境的区别。数据控制方面，用户可以自主决定代码和记忆存储在云端还是本地。

Step 04 · 深入技术原理

Harness Engineering：数字员工的「大脑架构」

了解了 Waker 是什么之后，下一个问题是：它是怎么工作的？QoderWake 扩展了行业标准的 Harness 工程体系，设计了四层架构来保证数字员工的可靠性。

类比 · 像理解一个餐厅那样理解架构

想象一个餐厅的运作：(1) 经理决定今天做什么菜、安排服务员分工（决策层）；(2) 厨师根据菜单理解客人需求、设计菜品（推理层）；(3) 厨房实际烹饪菜品，做好后由品控员检查（执行层）；(4) 点菜系统记录每一笔订单，即使断电重启也不会丢单（状态层）。

决策层

Orchestrator · 确定性流程编排

确保长时间运行任务的可靠性。就像一个项目经理，负责把大任务拆解成小步骤、按顺序推进、遇到问题时决定下一步。

推理层

LLM Model · 意图理解与推理

实现「脑-手-会话」解耦。LLM 负责理解你说的话、推理该怎么做，但不直接执行操作——它只负责「想」。

执行层

Executor · 任务生成与即时验证

独立验证器检查结果。执行产生结果后，由独立的验证器审查——如果验证失败，触发 REWORK 并记录失败原因作为未来知识。

状态层

Session · 所有组件的唯一状态源

崩溃后可完全重建；幂等恢复序列。所有组件共享同一个状态源，不会因为「各记各的」导致数据不一致。

双反馈循环：做完了还要检查

这是 QoderWake 架构中最精妙的设计之一。执行层不仅仅是「做完就完」——它有一个双重验证机制：

Executor 执行
→
产生结果
→
Verifier 验证
→
通过 ✓

验证失败时，触发 REWORK，失败原因记录为知识 → 下次避免同类错误

费曼检验 · 理解双反馈

就像考试做完后自己检查一遍。如果发现错误，不仅改答案，还要记住「这类题我容易错在哪里」——下次遇到同类题就自动多检查一次。这就是 QoderWake 的「经验转化为能力」机制。

Step 05 · 理解进化机制

越用越聪明，而不是越用越乱

很多人对 AI 工具的一个担忧是：用久了会不会变得「更乱」而不是「更好」？QoderWake 专门设计了进化与治理机制来解决这个问题。

类比 · 像培养一个实习生

Day 1 的实习生什么都不懂，需要你手把手教。但你教他的每一次，他都在记笔记、总结经验。到 Day 90，他已经成为熟悉你工作方式的资深员工——知道你喜欢什么代码风格、哪些模块要特别小心、哪些 PR 可以直接过。

QoderWake 的数字员工就是这样「成长」的。

三个关键机制

1. 统一信号 · 所有经验变成结构化知识

  • 对话、工具调用、检索、验证、纠正——全部转化为结构化学习信号
  • 不是简单的聊天记录，而是可以被系统理解和利用的知识

2. 轨迹归因 · 经验变成正确的东西

  • 系统分析完整的任务轨迹（不只是结果），决定经验应该沉淀为什么
  • 可能变成：记忆（长期认知）、技能（可复用操作）、策略（决策规则）、验证器（检查规则）、工作流（标准流程）

3. 抗腐化治理 · 旧知识不会拖后腿

  • 降权：过时的记忆和技能权重自动降低
  • 合并：冲突的技能会被智能合并
  • 撤回：无效的策略会被清理掉

Step 06 · 两种工作方式

对话派活 vs 自动执行

数字员工有两种工作模式，适用于不同场景。

对话任务 · 实时协作

直接在输入框输入需求，员工开始干活。过程中你可以：

追问 & 调方向
随时插话，员工接着上下文继续工作。
审批操作
要动文件、跑命令时会停下来征求同意，你点「允许」或「拒绝」。
切换模型
对话中途感觉不够聪明或想省成本，顶部下拉可以换模型继续。
实时观察
看思考过程、看产物产出，全程透明。

自动任务 · 无人值守

适合「每天跑一次」「监听仓库变化就自动响应」这类场景。支持三种触发方式：

触发方式场景示例
定时周期性任务每天 9 点生成日报、每周做一次代码审查
事件驱动响应外部变化GitHub Issue 变化时自动分析、PR 提交时自动 Review
网络回调第三方系统集成监控系统告警 → Webhook 触发员工诊断
Step 07 · 管理你的数字团队

五个管理维度

管理数字员工和管理真人团队有很多相似之处。你需要关注五个维度：

维度你能做什么关键特点
记忆管理 浏览、搜索、编辑员工的长期认知 自动沉淀 + 手动写入 + 系统定期整理。本地存储，不上传云端。
技能 安装、上传、开关技能包 从 Skills Marketplace 安装或自定义上传。内置技能不可卸载。
连接器 对接外部工具/服务 支持 GitHub、Jira、GitLab 等主流开发工具。
项目 绑定本地目录或 Git 仓库 一个项目可包含多个源。项目记忆与员工个人记忆分开。
权限 工具防护 + 文件防护 + 内置工具策略 检测命令注入、资源滥用、权限提升等。高危操作弹审批卡片。
费曼检验 · 权限红线像什么？

想象你给了新员工公司服务器的 SSH 权限，但你不希望他能 rm -rf /。QoderWake 的权限系统就是这个角色——它会检测命令注入、资源滥用、远程代码执行、反弹 Shell、敏感文件访问、权限提升等危险操作，命中高危规则时会暂停并弹出审批卡片让你确认。

Step 10 · 总结回顾

费曼教学法回顾：你能讲清楚了吗？

费曼学习法的最后一步是检验：你现在能不能用最简单的话，给别人讲清楚 QoderWake 是什么？

核心要点清单

  • QoderWake 是什么：一个在你本机上运行的数字员工平台，7×24 小时在线
  • 核心概念 Waker：每个数字员工有五层架构——身份、记忆、技能、分工、权限红线
  • 预置角色：后端/前端/测试/产品/数据/运营 + 自定义角色

  • 工作方式：对话任务（实时协作）+ 自动任务（定时/事件/回调触发）
  • 管理维度：记忆、技能、连接器、项目、权限
